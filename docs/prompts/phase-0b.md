# 阶段 0B：用代码从空白 Case 建出转化反应器（闸门 G0）

本文件是 `docs/prompts/phase-0b.md`。如果对话被压缩过，或者你不确定现在该做什么，重新读这个文件、`CLAUDE.md` 和 `docs/progress.md`。

## 你在做什么

这个项目要做一个系统：读入一段中文的反应过程描述，判断该用哪种反应器，在本机的 Aspen HYSYS V15 里真实地建模、求解并返回结果。

上一个会话（0A）已经连上了 HYSYS，导出了类型库，并从一个现成的 Case 里看清了反应器、反应和反应集在 COM 里的样子。结论都在 `docs/HYSYS_INTEGRATION.md`。

这个会话要回答全项目最关键的问题：**不靠任何手工操作，Python 能不能在一个空白的 HYSYS Case 里建出一台带反应的转化反应器，并算出正确的结果。** 能，后面的架构就成立。不能，就要在这个会话里弄清楚卡在哪一步，并给出替代做法的建议。

## 本阶段的目标

一个脚本 `spikes/e7_conversion_chain.py`，从空白 Case 开始，全程没有手工操作，建出下面的模型，求解，读出结果，并打印与解析解的对比。连续运行两次，两次都成功，结果一致。

### 要建的模型

| 项 | 内容 |
|---|---|
| 流体包 | Peng-Robinson |
| 组分 | 甲苯、苯、对二甲苯、间二甲苯、邻二甲苯 |
| 反应 | 转化反应：2 甲苯 → 1 苯 + 0.24 对二甲苯 + 0.52 间二甲苯 + 0.24 邻二甲苯。基准组分甲苯，转化率 50%，不随温度变化 |
| 反应集 | 包含这个反应，并加入流体包 |
| 进料 | 纯甲苯，10000 kg/h，380 °C，2500 kPa（绝压） |
| 反应器 | 转化反应器。一股进料，气相和液相两股出料，不接能流（绝热），压降为 0，挂上反应集 |

### 期望结果（解析解）

进料 10000 kg/h ÷ 92.14 kg/kmol = 108.53 kmol/h。反应前后总摩尔数不变。

| 组分 | 出口摩尔流量 kmol/h | 出口摩尔分率 | 出口质量流量 kg/h |
|---|---|---|---|
| 甲苯 | 54.26 | 0.500 | 5000 |
| 苯 | 27.13 | 0.250 | 2119 |
| 对二甲苯 | 6.51 | 0.060 | 691 |
| 间二甲苯 | 14.11 | 0.130 | 1498 |
| 邻二甲苯 | 6.51 | 0.060 | 691 |

这个反应的热效应很弱，绝热出口温度应当接近 380 °C。380 °C 高于甲苯的临界温度，进料是单一气相，液相出口流量为零是正常的。

## 任务

按顺序做。每一步做完立刻用 COM 读回验证，并在台账的探索日志里记一条，再做下一步。不要把整条链写完再一起调试，那样出错时分不清是哪一步的问题。

### 1. 新建 Case 和 Basis（E4）

`spikes/e4_basis.py`。要弄清并记录：

- 怎么用代码新建一个空白 Case，怎么另存、关闭、重新打开
- 怎么新建流体包并指定 Peng-Robinson，物性包的名字在 COM 里是什么字符串
- 怎么向流体包添加库组分，五个组分在 HYSYS 组分库里的确切名字是什么。把它们填进台账的"组分规范名"一节
- 修改 Basis 是否需要包在"开始修改、结束修改"的事务里
- 组分库能不能按名称或分子式检索。这关系到以后遇到新组分时怎么找到它的规范名

### 2. 新建物流（E5）

`spikes/e5_stream.py`。新建一股物流，规定温度、压力、质量流量、组成，确认它闪蒸完成（气相分率等计算值变为已知）。记录每个量的写入方式和单位字符串。组成按摩尔分率写入；后面的正式代码只用摩尔分率这一种写法。

### 3. 创建反应和反应集（E6）

`spikes/e6_reaction.py`。这是全项目风险最高的一步。

目标是用代码创建一个转化反应（计量系数、基准组分、转化率），创建一个反应集，把反应放进去，再把反应集加入流体包。

做法：从 0A 留下的线索开始，一条一条试。每试一条，把调用形式和结果（成功，或者报什么错）记进探索日志，然后再试下一条。

验证分两步。先用 0A 反向探测时读取反应的那些成员，把刚创建的反应读回来，看计量系数、基准组分、转化率是否和设定的一致。读回一致之后，把 Case 另存到 `spikes/out/`，请我在 HYSYS 界面里打开它，看一眼反应页面做最后确认。读回的值是你自己刚写进去的，它一致不等于 HYSYS 真的认可了这个反应；真正的证明是任务 4 里出料的组成变了。

### 4. 转化反应器全链路（E7）

`spikes/e7_conversion_chain.py`。在前三步的基础上：

- 用 0A 查到的类型名创建转化反应器
- 连接进料、气相出料、液相出料
- 挂上反应集，设压降为 0
- 释放求解器，等待求解完成
- 读出料的温度、压力、流量、组成，打印与期望结果的对比表和质量守恒误差

同时弄清并记录：求解是随着调用同步完成的，还是需要等待；用什么判断"已经求解完成"；模型没有求解时，从哪里能读到原因（哪个量没有规定）；建模期间求解器要不要先挂起。

这个脚本会成为后面 Backend 的蓝本，所以把它按步骤拆成几个函数，写得清楚一些。

### 5. 并行的转化反应（G0 通过之后做）

后面的阶段要支持"同一个基准组分有主、副两个反应，各有各的转化率"这种情况，所以需要知道 HYSYS 怎么处理并行的转化反应。

在 `spikes/e6b_parallel_reactions.py` 里，把任务 3 的一个反应换成三个转化反应，基准组分都是甲苯，各生成一种二甲苯，转化率分别是 12%、26%、12%，其余不变。

- 三个反应的排序设置相同（并行）时，出口甲苯的摩尔分率应当是 0.500。
- 再把排序设成依次进行，看结果怎么变。如果后一个反应的转化率是对前一个反应剩下的甲苯算的，甲苯会剩下 (1 − 0.12) × (1 − 0.26) × (1 − 0.12) = 0.573，出口甲苯的摩尔分率就是 0.573。用这两个数判断排序的含义。

把排序对应的成员名、取值的含义，以及"并行"该怎么设，记进台账。任务 3 如果因为分数系数写不进去而已经改用了三个并行反应，这一步就只需要补上排序含义的判断。

## 难点

**创建反应的接口没有公开文档。** 这就是为什么要逐条试、逐条记。常见的可能性包括：Basis 一侧某个集合对象的 `Add` 方法、流体包上与反应相关的成员、需要先创建反应集再在集合里添加反应。参数里可能要传反应类型的名字或枚举值，0A 反向探测时读到的类型名是最可靠的来源。

**分数计量系数可能不被接受。** 如果 0.24、0.52 这样的系数写不进去，改用三个并行的转化反应（见任务 5 的设置），并把"分数系数不可用"记进台账。后面的 Recipe 要根据这条结论决定怎么建。

**模型不求解。** 常见原因是自由度没有用完或者用过了头：压降没有规定、液相出口没有接、反应集没有加入流体包、反应集里的反应类型与反应器类型不匹配。先读对象的状态信息，再对照参考 Case 里那台反应器的设置找差别。

**读错对象。** 确认出料的组成确实和进料不同，转化率确实是 50%。不要因为读到了一组数字就认为成功。

**残留状态。** 每次运行都从新的空白 Case 开始。偶然遇到同名对象已经存在时的行为，顺手记下来；系统的测试在 0C 做。

## 受阻时怎么办

计划 §16.5 定义了几级集成方式。第一级是全部用 COM 编程创建，这是目标。

- 第一级在某一步走不通时，先试第二级：类型库里其他能访问内部变量的通道。第二级最多再花 60 分钟。
- 第三级（预置一个只含骨架的种子 Case）和第四级（对那一步做界面自动化）需要我配合，而且会削弱"由系统实际创建反应器"这一条。**不要自行降到这两级。** 把卡住的那一步、试过的所有做法、你建议的降级方式写进进度文件，然后停下来问我。这时我可能会让下一个会话先做 0C 里的备选路线对照，它的结论决定往哪个方向降级。

判断"走不通"的标准：针对同一步换了 5 种不同的思路都失败，或者这一步用了超过 90 分钟。
