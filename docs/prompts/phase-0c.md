## 你在做什么

这个项目要做一个系统：读入一段中文的反应过程描述，判断该用哪种反应器，在本机的 Aspen HYSYS V15 里真实地建模、求解并返回结果。

上一个会话（0B）回答了最关键的问题：转化反应器能不能完全用代码从空白 Case 建出来。调用序列记在 `docs/HYSYS_INTEGRATION.md` 里。这个会话完成探索阶段剩下的部分：另外两种反应器、固体碳、几项鲁棒性观察，以及对备选技术路线的一次对照。做完之后，项目里就不再有未经验证的 HYSYS 假设了。

需求文档把"探索实现路径"列为最重要的考核要素，评分点之一是"是否展示了独立探索不同方案的过程"。所以备选路线对照那一项任务不是为了实现功能，而是为了留下一份有证据的路线对比。

## 任务

### 1. 平衡反应和平衡反应器（E8）

`spikes/e8_equilibrium_chain.py`。

| 项 | 内容 |
|---|---|
| 流体包 | Peng-Robinson，组分为甲烷、水、CO、CO2、氢气 |
| 反应 | 两个平衡反应：CH4 + H2O ⇌ CO + 3 H2，CO + H2O ⇌ CO2 + H2。平衡常数由 Gibbs 自由能计算 |
| 反应集 | 包含两个反应，加入流体包 |
| 进料 | 520 °C，1350 kPa，3700 kmol/h，摩尔分率 CH4 0.2703、H2O 0.7297 |
| 反应器 | 平衡反应器。一股进料，气、液两股出料，一股能流，压降为 0 |
| 工况 | 先把出口温度规定为 710 °C 并求解；再改成 600 °C 重新求解 |

参照值（独立计算的理想气体平衡，不是 HYSYS 的结果）：

| 量 | 710 °C | 600 °C |
|---|---|---|
| CH4 转化率 | 约 55% | 约 30% |
| 出口湿基摩尔分率 CH4 / H2O / H2 / CO / CO2 | 0.094 / 0.381 / 0.411 / 0.047 / 0.067 | 0.162 / 0.499 / 0.269 / 0.012 / 0.058 |
| 出口总摩尔流量 | 约 4800 kmol/h | 约 4305 kmol/h |
| 热负荷 | 吸热 | 吸热，小于 710 °C 工况 |

五个组分的摩尔分率与参照值各自相差不超过 0.02 算通过。

要弄清并记录：

- 平衡反应的 Keq 来源怎么设置、默认是什么
- 出口温度是规定在出料物流上还是反应器上
- 改规定之后模型是否自动重算
- 能流的热负荷怎么读，单位是什么，吸热时符号是正还是负

另外用固定的 Keq 数值试一次，确认"用户直接给出平衡常数"这种情况能不能通过代码设置，记录调用形式。不要求结果对比。

Keq 来源设不成 Gibbs 自由能时，按计划 §17.1"异常"里的顺序处理：先看默认来源是什么，再试 HYSYS 内置的平衡反应库。再往下要用到预置的种子 Case，先停下来问我。

### 2. Gibbs 反应器，纯气相（E9）

`spikes/e9_gibbs_gas.py`。用任务 1 的进料和组分，不建反应、不挂反应集，使用 Gibbs 反应器的纯自由能最小化模式，出口温度 710 °C。结果应当与任务 1 的 710 °C 工况很接近，因为五个组分、三种元素恰好对应两个独立反应。记录 Gibbs 模式怎么设置。

在这个模型上再做两个小试验，各求解一次并记录做法：

- 把进料拆成甲烷和水蒸气两股，分别接进反应器。确认多股进料怎么接。
- 去掉能流，让反应器绝热。确认绝热模式能求解，出口温度作为结果读出。

### 3. 固体碳（E10）

`spikes/e10_gibbs_carbon.py`。

| 项 | 内容 |
|---|---|
| 流体包 | Peng-Robinson，组分为碳、水、CO、氢气、CO2、甲烷 |
| 进料 | 40 °C，4000 kPa，总摩尔流量 3569 kmol/h，摩尔分率碳 0.710、水 0.290（由质量分率 0.62、0.38 换算）。写入后读回质量分率，核对是否是 0.62 和 0.38 |
| 反应器 | Gibbs 反应器，纯自由能最小化模式。一股进料，气、液两股出料，一股能流，压降为 0，出口温度 1400 °C |

参照值：出口气体 CO 约 1017 kmol/h、H2 约 981、CH4 约 22、H2O 约 11、CO2 约 3.5；未反应的固体碳约 1491 kmol/h；CO 收率（出口 CO 摩尔流量除以进料碳摩尔流量）约 40%；所需的外供热约 85 MW。

通过的条件，四条都要满足：

- CO 收率在 38% 至 42% 之间。
- 气相出料里 CO 和 H2 的摩尔分率与 0.500、0.482 各自相差不超过 0.02。
- 碳元素守恒：进料的碳等于各股出料里 CO、CO2、CH4 和未反应碳的碳之和，相对误差不超过 0.1%。
- 没有反应掉的碳以固体的形式从某一股明确的出料离开，量与 1491 kmol/h 相差不超过 5%。

只看 CO 的量是不够的：水是限量的反应物，即使 HYSYS 把碳当成了普通的气相组分，CO 的量也会差不多对。能暴露问题的是碳的相态、去向，以及甲烷、水、CO2 这些小量组分的分布。如果没反应掉的碳出现在气相出料里，结论就是"碳没有作为固体参与平衡"。

要有明确答案的五个问题：

- 组分库里有没有碳，叫什么名字，HYSYS 把它当作什么相
- 含固体的进料物流在 40 °C 能不能正常闪蒸
- Gibbs 反应器是否让碳作为固体参与平衡
- 没有反应掉的碳从哪股出料离开
- 碳元素是否守恒

进料物流出问题时，改成碳和水两股进料分别进反应器再试。同时读出能流的热负荷，与约 85 MW 对照量级。

如果 Gibbs 反应器不能正确处理固体碳，计划 §17.3 给了一个两段式的替代做法。**不要自行改用它**，它会改变模型的结构。把现象和证据写进进度文件的"待决策"并问我，同时继续做后面的任务，它们不依赖这一项。

### 4. 鲁棒性观察（E11）和保存重开（E12）

`spikes/e11_robustness.py`、`spikes/e12_save_reopen.py`。这些观察决定后面错误码和恢复策略怎么设计，所以要记下异常的类型和消息原文。

- **同名对象。** 在已经建好模型的 Case 里再跑一遍建模步骤，记录每个创建调用遇到同名对象时的表现：报错、覆盖、还是自动改名。
- **进程中断。** 用 0A 记录的办法取得 HYSYS 的进程号。主线程做 COM 调用，另用一个定时器在几秒后执行 `taskkill /F /PID <进程号>`。分别在"两次调用之间"和"保存或打开 Case 期间"各试一次，记录 Python 一侧拿到的异常类型、错误号和消息。
- **弹窗。** 主动制造三种情况，看 COM 调用会不会被对话框卡住：关闭一个改过但没保存的 Case；打开一个不存在的文件；另存到一个不存在的目录。把被测的调用放进一个带超时的子进程里，超时就说明被卡住了。窗口隐藏时再试一次最容易卡住的那种。
- **窗口隐藏。** 窗口不可见时建模和求解是否正常。
- **保存重开。** 保存已求解的 Case，关闭后重新打开，结果是否一致，求解状态是否保留。另存之后，活动 Case 的路径是原来的还是新的。

## 难点

**参照值不是标准答案。** 它们是理想气体假设下的独立计算。HYSYS 用自己的物性数据和状态方程，有小的偏差是正常的。偏差超过容差时，先检查模型是不是建错了：组成、压力单位、Keq 来源、平衡常数的基准、反应的相态。不要去调整模型让数字凑上。

**固体碳的结果可能"看起来合理但是错的"。** 见任务 3 的通过条件。

**路线对照容易做成走过场。** 每条路线至少要有一个实际运行的结果作为证据，哪怕结果是"控件树里找不到可操作的元素"。
