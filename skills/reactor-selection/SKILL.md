# 反应器选型

读一段反应过程的描述，做两件事：抽取下面的特征，并推荐一种反应器类型。

系统会用同一组特征按固定的规则独立推出结论，再和你的推荐对照。两者不一致时，会请你对照原文重新核对特征。所以特征要如实抽取，不要为了凑出某个结论而改变特征的取值。

## 可选的类型

`conversion`（转化反应器）、`equilibrium`（平衡反应器）、`gibbs`（吉布斯反应器）、`pfr`（平推流反应器）、`cstr`（全混流反应器）。

描述的不是反应过程时，`recommended_type` 填 `null`。

选型依据在《选型规则》里，容易判错的地方在《容易判错的情况》里，示例在后面。先读完再判断。

## 特征

下面每个特征的含义里都有区分，选型对不对取决于这些区分，请按字面理解。

| 特征 | 取值 | 含义 |
|---|---|---|
| `is_reaction_process` | 是、否 | 用户要模拟的是不是一个发生化学反应的过程。要模拟精馏塔、换热器、泵这类不发生反应的设备，就是“否” |
| `named_reactor` | 五种类型之一，或空 | 用户明确说了用哪种反应器**模型**才算。“焚烧炉”“加热炉”“反应釜”“管式反应器”是设备的叫法，不算点名 |
| `kinetics_given` | 是、否 | 原文里有速率常数、指前因子、活化能、反应级数这类数值。只说“反应很快”“有催化剂”不算 |
| `dimensions_given` | 是、否 | 原文里有反应器的体积、管长、管径 |
| `equipment_form` | `tubular`、`vessel`、`unspecified` | 用户说明了反应器是管式还是釜式。没有说明就是 `unspecified` |
| `conversion_data_given` | 是、否 | 原文里有转化率、收率或选择性的数值，并且是作为**已知条件**给出的，也就是模拟要照着它来。“请计算收率”“求转化率”里的指标是待求量，不算 |
| `reaction_defined` | 是、否 | 用户把要模拟的每个反应都说清楚了：用反应方程式写出，或者用文字说明了反应物和产物（不要求化学式，不要求配平），并且没有要求再考虑没有列出的反应。叫“主反应”还是“副反应”不重要，关键是每一个都说清了、没有留下“还有别的”。只写了一个“主要反应”又要求考虑副反应，或者只说“发生反应”而没说清反应物和产物，就是“否” |
| `black_box_system` | 是、否 | 满足下面任何一条才是“是”：①过程本身是气化、燃烧、裂解（热解、焚烧）这一类，高温、不靠催化剂、机理复杂，会生成许多事先列不全的产物；②用户明说不清楚会生成哪些产物。靠催化剂实现、产物种类确定的转化不属于这一类，温度再高、反应吸热、反应不止一个也不算。“要求算出产物分布”是任何模拟的目的，不是“产物未知” |
| `equilibrium_constant_given` | 是、否 | 原文里有平衡常数 Keq 或 Ka 的数值或表达式（包括随温度变化的关系式） |
| `phase` | `gas`、`liquid`、`multiphase`、`unknown` | 反应物的相态。气液、气固液共存等是 `multiphase`，原文没有足够信息是 `unknown` |
| `polymerization` | 是、否 | 反应是聚合反应（加聚、缩聚、自由基聚合等） |

## 输出要求

- 按给定的结构输出，字段顺序就是推理的顺序：先逐个特征，再给推荐。
- **依据（`evidence`）**：取值为“是”的特征，以及 `named_reactor` 不为空时，都要附一条依据。依据必须是用户原文里的**原话**，逐字摘抄（包括标点、数字和错别字），一般取一句话或一个短语；不要改写、概括、翻译，不要用省略号把几处拼在一起。取值为“否”的特征不附依据。
- **理由（`rationale`）**：2 到 5 句话。先说关键特征（引用原文里的事实），再说它对应选择逻辑的哪一条。
- **备选（`alternatives`）**：对推荐类型之外的每一种类型，各写一条不选它的原因（一句话：缺少什么必要输入，或者按选择逻辑优先级更低）。描述的不是反应过程时，备选为空。
- 原文没有给的信息不要补。拿不准的特征按字面取“否”或 `unknown`，不要猜。
